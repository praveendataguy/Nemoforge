What NemoForge does

You describe a job in one sentence. NemoForge designs a small team of AI agents for it, writes their tools, tests the team on cases it has never seen, improves it round by round and ships the best version. Everything runs on NVIDIA Nemotron through Nebius Token Factory.

The build pipeline
  1. Architect (Ultra) designs the team: agents, order, tools, model per agent.
  2. Toolsmith (Super) writes each custom Python tool and checks it in a sandbox.
  3. Test designer (Ultra) writes test cases; a third are held out and never shown to the optimizer.
  4. Evaluate: the team answers every test and a Super judge grades each answer. If it marks an answer as failed, Ultra gives a second opinion, so one harsh grade can't sink a good answer.
  5. Optimizer (Ultra) reads the failures and fixes prompts, tools or tiers.
  6. Healer (Ultra) steps in when the build is stuck or crashes, then a bonus round checks the repair.
  7. The best round ships. Try it in the playground or deploy it.
Smart router

Before every agent runs, Nano rates the request from 1 to 5: 1-2 run on Nano, 3-4 on Super, 5 on Ultra. It never drops more than one tier below the Architect's plan. The routing panel shows every decision and the money saved.

Held-out tests and overfitting

The held-out score is the honest number. If training rises while held-out falls, NemoForge flags overfitting and ships an earlier, better version.

Observability and severity

Every input is a log record: build goals, graded tests and playground runs. critical crashes, high weak held-out or big gaps, medium below target or interrupted, low notes such as repairs, info all good.

Agent memory

Each agent remembers the lessons from its own build (what the Optimizer and Healer fixed) and its latest playground runs. Tick Use memory in the playground to give the team the 3 earlier runs most related to the new request, ranked by meaning with a Nebius embedding model, for example to follow up on open items from a related meeting.

Nemotron reasoning

Every call sets Nemotron's reasoning switch per tier: Ultra and Super think step by step, Nano answers directly to stay fast and cheap. The Nemotron reasoning panel in a build shows what Ultra and Super were thinking.

Budget, settings and CLI

The budget is a hard stop per build. Lite mode sends Ultra's jobs to Super. A build passes when both training and held-out scores reach the target (85% by default, NF_PASS_THRESHOLD). Settings: NEBIUS_API_KEY, TAVILY_API_KEY, NF_PASS_THRESHOLD, NF_SMART_ROUTING, NF_HEAL_ROUNDS, NF_OWNER. Put them in a .env file in the project folder, or set them in the terminal.

python -m nemoforge serve
python -m nemoforge build "goal" --budget 1
python -m nemoforge run <build-id> "input"
python demo/batch_test.py --total 1

Self-healing
